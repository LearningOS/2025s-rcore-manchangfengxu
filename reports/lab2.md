# 一.实现功能

## 1.实现根据虚拟地址的读写:
### 具体实现:
根据虚拟地址得到虚拟页号,通过memory_set.translate(vpn)得到pte,判断是否可读可写.
将pte的bits转为ppn(去掉表示为),并转为物理地址,加上虚拟地址的偏移得到.
### 注意:
虚拟地址不能大于1<<39 -1

## 2.实现按页分配的内存映射:
### 具体实现:
根据_start和_len得到始末的虚拟地址,_start.floor()和(_start+_len).ceil()得到始末的虚拟页号.
遍历始末的虚拟页号(末除外),判断是否已经映射.is_vailed
通过memory_set.map(vpn,ppn)将虚拟页号映射到物理页号.
### 注意:
* _start+_len不能大于1<<39 -1
* 按页映射为左闭右开

## 3.实现按页取消的内存映射:
### 具体实现:
根据_start和_len得到始末的虚拟地址,_start.floor()和(_start+_len).ceil()得到始末的虚拟页号.
遍历始末的虚拟页号(末除外),判断是否已经映射.is_vailed
通过memory_set.unmap(vpn)取消映射.
### 注意:
* _start+_len不能大于1<<39 -1
* 按页映射为左闭右开

# 二.问答
## 1.请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？
组成:
* PPN:物理页号,56位物理地址,前12位位偏移,13到55为页号
* VPN:虚拟页号,39位虚拟地址,前12位为偏移,13到38为页号
* R/W:读/写权限
* X:执行权限
* U:用户是否可访问
* A:A(Accessed) 记录自从页表项上的这一位被清零之后，页表项的对应虚拟页面是否被访问过；
* D(Dirty) 则记录自从页表项上的这一位被清零之后，页表项的对应虚拟页表是否被修改过。
* V:有效位

## 2.缺页
### 缺页的原因
* 未映射的虚拟页
* 读/写权限不够
* 页表项无效
### 缺页时寄存器
* stval (Supervisor Trap Value): 保存导致异常的虚拟地址。对于页错误，它会包含无法完成访问的那个虚拟地址。
* sepc (Supervisor Exception Program Counter): 保存发生异常的指令的地址。OS 处理完异常后，通常会返回到这个地址（或者这个地址的下一条指令，取决于异常类型和处理方式）。对于缺页，通常需要重新执行 sepc 处的指令。
* scause (Supervisor Cause): 保存异常的原因代码。(缺页原因)
### lazy策略的好处
* 节省内存
* 提高程序启动速度
* 对于系数内存分配,减少页表建立的开销
* 按需分配
### 10g 虚拟地址,所需页表存储
约等于20MB
如何实现 Lazy 策略及缺页处理？

- 实现 Lazy 策略：
  - 当用户请求 mmap 一段内存时，不在页表中立即创建对应的 PTEs，也不分配物理页帧。
  - 在MapArea中记录下这个虚拟地址范围、权限等信息，并标记为“懒分配”。
- 缺页处理：
  - 当进程访问这个范围内的某个地址时，由于没有有效的 PTE（V=0），会触发页错误。
  - 操作系统捕获到页错误异常，检查 stval 中的故障地址。
  - 查询MapArea，确认该地址是否属于一个已记录的、合法的、但尚未分配物理页面的区域。
  - 如果是：
    1. 分配一个物理页帧。
    2. 在页表中创建或更新对应的 PTE，将虚拟页号映射到新分配的物理页号，设置正确的权限位（R, W, X, U）并将 V 位置 1。
    3. 更新 A/D 位（通常硬件会自动处理，但 OS 可能需要软件管理）。
    4. 返回，并重新执行 sepc 处的指令。
  - 如果不是 （地址无效或权限不符）：则判断为段错误（Segmentation Fault），终止进程或发送信号。
## 3.双页表与单页表
### 在单页表情况下，如何更换页表？

- 在同一个进程的用户态和内核态之间切换时，通常不需要更换页表。 satp 寄存器（指向页表基地址）保持不变。切换只涉及特权级的改变（U-mode <-> S-mode）和栈指针的切换。
- 页表更换只发生在进程上下文切换时 ，即从一个进程切换到另一个不同的进程时，才需要将 satp 指向新进程的页表基地址，并可能需要刷新 TLB。
### 单页表情况下，如何控制用户态无法访问内核页面？

通过 PTE 中的 User (U) 位 来控制。

- 对于映射内核代码、数据、栈等的页面，其对应的 PTE 的 U 位被 清零 (U=0) 。
- 当 CPU 处于用户模式（U-mode）时，如果尝试访问一个 U=0 的页面，硬件会阻止访问并触发页错误异常。
- 当 CPU 处于super模式（S-mode，即内核态）时，它可以访问 U=0 和 U=1 的页面（只要 V=1 且 R/W/X 权限允许）。
### 单页表有何优势？

1. 性能较高： 用户态和内核态之间的转换（系统调用、中断返回）不需要切换页表（改变 satp ）和大规模刷新 TLB。TLB 中缓存的用户和内核地址映射可以继续有效，减少了 TLB Miss 的开销，提高了转换速度。
2. 实现相对简单。

### 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表？

- 双页表实现下（如 KPTI）：
  - 每次 从用户态进入内核态（系统调用、中断、异常）时，需要切换到内核专用的页表（修改 satp ）。
  - 每次 从内核态返回用户态时，需要切换回用户进程的页表（修改 satp ）。
  - 在进行 进程上下文切换 时，也需要切换到目标进程的用户页表（如果下一个状态是用户态）或内核页表（如果下一个状态是内核态）。
- 单页表操作系统下：
  - 我会选择 仅在进行进程上下文切换时 更换页表。即，当操作系统调度器决定停止当前进程运行，并开始运行另一个不同的进程时，才将 satp 指向新进程的页表基地址。在同一进程的用户态和内核态之间切换时，不更换页表。
